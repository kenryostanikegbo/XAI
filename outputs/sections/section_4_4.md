## SHAP as the Interpretability Framework

This section explains why SHAP was chosen as the interpretability framework for the present study, what guarantees it offers, and what limitations bound the conclusions that can be drawn from a SHAP analysis. The analytical use of SHAP in the present study is reported in §4.6 (global) and §4.7 (local); the cross-model comparison in §4.8 relies on the properties explained here.

### Why SHAP

The interpretability requirement of the present study is twofold: the explanations must be faithful to the model being explained (so that a tutor who sees a SHAP plot can trust that the plot reflects what the model actually computed), and the explanations must be comparable across model families (so that the cross-model comparison in §4.8 is well-defined). These two requirements rule out most of the standard alternatives. Permutation importance is faithful but is not local — it gives a single number per feature, not a per-instance attribution. LIME (Ribeiro et al., 2016) is local and model-agnostic but is not guaranteed to be consistent across runs and is not directly comparable across model families without re-fitting local surrogate models. The coefficients of a Logistic Regression are local and faithful but are not model-agnostic. TreeInterpreter for the Random Forest gives attributions that are local and faithful but only for tree ensembles.

SHAP (SHapley Additive exPlanations; Lundberg & Lee, 2017) is the only framework that is simultaneously local, faithful, model-agnostic in principle, and defined for both linear and tree-ensemble models. The local property means that each prediction gets its own explanation. The faithfulness property means that the SHAP values sum to the model's output, so the explanation is exact rather than approximate. The model-agnosticism is implemented in practice through two specialised explainers: LinearSHAP for linear models and TreeSHAP for tree ensembles. Both explainers return attributions that are expressed in the same conceptual units (signed contributions to the model's output), and that is the basis on which the cross-model comparison in §4.8 can compare a log-odds attribution to a probability attribution by sign rather than magnitude.

### The Shapley Value Foundation

SHAP values are Shapley values from cooperative game theory (Shapley, 1953), applied to the prediction problem. The interpretation is that each feature is a "player" in a cooperative game whose "payout" is the model's prediction, and the Shapley value of a feature is its average marginal contribution across all possible coalitions of features. The Shapley value is the unique attribution method that satisfies three desirable properties: local accuracy (the attributions sum to the model's output), consistency (if a model changes so that a feature contributes more, the attribution for that feature does not decrease), and missingness (a feature that is not present in the model receives an attribution of zero). The Shapley foundation is the reason that SHAP is preferred over LIME for the present study: LIME does not satisfy consistency in general, and the present study's cross-model comparison depends on a consistent attribution method.

### LinearSHAP for Logistic Regression

For a linear model of the form `f(x) = b + Σ w_i * x_i`, the SHAP value for feature `i` is `φ_i = w_i * (x_i - E[x_i])`, where the expectation is taken over the background dataset. LinearSHAP computes this analytically rather than by enumeration, and the result is a single signed attribution per feature per instance. The attribution is expressed in the same units as the model's output: for a Logistic Regression on the log-odds scale, the attribution is in log-odds units. The base value (the model's average prediction over the background dataset) is also in log-odds units, and the sum of the base value and the SHAP values equals the model's prediction for the instance. This additivity property is what makes the waterfall plots in §4.7 readable: the reader can see the base value, the contributions of each feature, and the final prediction, all in the same units.

### TreeSHAP for Random Forest

For a tree-ensemble model, the SHAP value for feature `i` is again a signed attribution per feature per instance, but the computation is more involved than for a linear model. Lundberg et al. (2020) developed TreeSHAP, a polynomial-time algorithm that exploits the tree structure to compute exact SHAP values in `O(TLD^2)` time, where `T` is the number of trees, `L` is the maximum number of leaves in any tree, and `D` is the depth. The result is exact (not approximate) and is computed without reference to a background dataset; the expected value is computed internally from the tree structure. The attribution is expressed in the same units as the model's output: for a Random Forest classifier that outputs probabilities, the attribution is in probability units. The base value is the average prediction over the training set, and the sum of the base value and the SHAP values equals the model's prediction for the instance, exactly as for the linear case.

### Additivity and Cross-Model Comparison

The additivity property — that the SHAP values sum to the model's output minus the base value — is what makes the cross-model comparison in §4.8 meaningful. For each instance, the sign of the SHAP value indicates the direction of the feature's contribution: positive for features that push the prediction toward Fail and negative for features that push toward Pass. This directionality is comparable across the two explainers, even though the magnitudes are not (log-odds for the Logistic Regression, probability for the Random Forest). The cross-model comparison in §4.8 uses both rank-based statistics (Spearman, Jaccard), which are scale-invariant, and a sign-based per-instance agreement table, which is also scale-invariant. Both are well-defined only because the SHAP framework offers a consistent notion of feature contribution across the two model families.

### Limitations of SHAP in the Present Study

Two limitations bound the conclusions that can be drawn from the present SHAP analysis. First, SHAP values are statistical associations, not causal effects (Chapter 2 §2.4). A feature with a large positive SHAP value on average is a feature that is associated with the model's prediction of Fail; it is not necessarily a feature whose manipulation would change the prediction in a deployed setting. The present study cannot, on the basis of observational data alone, support a causal reading of any SHAP value, and any future work that aims to support a causal reading would need to combine the SHAP analysis with a causal-inference framework (Chapter 5 §5.5 direction 5). Second, the SHAP values are computed with respect to the model's prediction, not with respect to the true outcome. A feature that the model uses heavily may be a feature that the model has learned to overweight rather than a feature that is genuinely informative about the outcome. The two limitations are related but distinct, and both should be flagged when the present findings are read.

### Reading SHAP Plots

The SHAP plots in §4.6 (beeswarm and bar chart) and §4.7 (waterfall) follow the conventions of the `shap` Python package (Lundberg et al., 2020). In a beeswarm plot, each dot is one test instance, the horizontal position is the SHAP value, and the colour encodes the feature value (red for high, blue for low). In a bar chart, each bar is the mean absolute SHAP value across the test set, and the bars are sorted descending. In a waterfall plot, each row is one feature, the bar length is the SHAP value, the colour is red for positive and blue for negative, and the bottom row shows the model's final prediction. A reader who is unfamiliar with these conventions is referred to Lundberg et al. (2020) for the full documentation; the conventions are used consistently throughout §4.6 and §4.7.
